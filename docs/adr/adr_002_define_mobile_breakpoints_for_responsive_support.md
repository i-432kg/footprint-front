# ADR: モバイル対応の基準端末幅を iPhone 13 を起点に定義する

## ステータス
Proposed

## 背景
現状の `footprint-front` は PC 画面を前提としたレイアウトが多く、モバイル端末での利用を考慮した設計が十分に整理されていない。

この状態で個別画面ごとにモバイル対応を進めると、画面ごとに異なる幅を基準に調整が入り、以下のような問題が起きやすい。

- ある画面では `390px` を前提に調整し、別の画面では `375px` を前提にする
- 余白やカード列数、モーダル幅の切り替え条件が画面ごとにばらつく
- 実機確認時に「どの幅で崩れなければよいか」の合意がない

今回、実機として所有している端末は iPhone 13 である。
そのため、まずは iPhone 13 の表示幅を起点にしつつ、より狭い iPhone 系端末とタブレット境界を吸収できる基準幅を定める必要がある。

## 問題
- モバイル対応の基準幅が未定義である
- 画面ごとに場当たり的なレスポンシブ調整が入るリスクがある
- 実機確認とブラウザ上のレスポンシブ確認の基準が揃っていない
- 将来の改修時に、どの幅まで保証すべきか判断しづらい

## 決定
モバイル対応の設計・実装・確認に使う基準幅を次の 3 段階で定義する。

1. `390px`: iPhone 13 実機を基準とした最優先幅
2. `375px`: より狭い iPhone 系端末を吸収するための下限確認幅
3. `768px`: タブレット縦向きおよびレイアウト切り替え境界の確認幅

加えて、余裕がある場合の補助確認幅として次を扱う。

- `320px`: かなり狭い端末で横スクロールを発生させないための下限チェック
- `430px`: 大きめ iPhone 系端末で間延びや余白過多を確認するための補助幅

## 設計方針

### 1. iPhone 13 の `390px` を設計起点にする
所有実機が iPhone 13 であり、日常的に最も確認しやすい端末であるため、最初に成立させるべきモバイル幅を `390px` とする。

確認対象の代表例:

- ヘッダー内のナビゲーション、検索 UI、アイコン操作
- 投稿カード一覧の横幅、余白、文字詰まり
- モーダルやフォームの幅、閉じる導線、スクロール挙動
- マップや画像の表示領域

### 2. `375px` を実質的なモバイル下限として扱う
`390px` だけで調整すると、少し狭い iPhone 系端末で折り返しやはみ出しが発生しやすい。

そのため、通常のモバイル対応では `375px` までを保証対象に含める。

期待する条件:

- 横スクロールが発生しない
- ヘッダー操作が崩れない
- 主要 CTA ボタンがタップ可能な大きさを維持する
- モーダルやカード内コンテンツが窮屈になりすぎない

### 3. `768px` をレイアウト切り替えの主要境界とする
`768px` はタブレット縦向きや、モバイル 1 カラムから複数カラムへ戻す境界として扱いやすい。

この幅を基準に、次のような切り替えを設計する。

- モバイルでは 1 カラム
- タブレット以上では 2 カラム以上
- サイドバーはモバイルでは折りたたみまたはメイン下へ移動
- モーダルはモバイルでは `fullscreen` 寄り、タブレット以上では固定幅

### 4. 補助確認幅は品質確認用とし、主設計の軸にはしない
`320px` と `430px` は補助的な検証幅として扱う。

- `320px`: 完全最適化を目的とせず、重大な崩れや横スクロールがないことを確認する
- `430px`: `390px` 向けに詰めすぎた UI が不自然に見えないことを確認する

設計の主軸はあくまで `390px`、`375px`、`768px` の 3 点とする。

## 選択肢

### 案1: iPhone 13 の `390px` のみを基準にする
不採用。

理由:

- 実機基準としては分かりやすいが、少し狭い端末での崩れを吸収できない
- 画面によっては `390px` では成立しても `375px` で破綻する

### 案2: 多数の端末幅を細かく基準化する
不採用。

理由:

- 初期対応としては過剰で、実装判断が複雑になる
- 画面ごとの差分調整が増え、保守性が落ちる

### 案3: `390px`、`375px`、`768px` を主基準とし、`320px` と `430px` を補助確認幅とする
採用。

理由:

- 実機起点で現実的に確認しやすい
- 狭いモバイル端末からタブレット境界までを少ない基準でカバーできる
- レイアウト切り替え条件を画面横断で統一しやすい

## 実装ガイド
レスポンシブ対応の実装では、まず次の 3 区分で UI を設計する。

1. `<= 375px`: 狭小モバイル
2. `376px - 767px`: 標準モバイル
3. `>= 768px`: タブレット以上

Vuetify の `useDisplay()` を利用し、画面ごとに独自の境界を増やしすぎない。

対象例:

- `Header.vue`: ナビゲーションと検索 UI の簡略化
- `TwoColumnLayout.vue`: モバイル時の 1 カラム化とサイドバー導線の再配置
- 一覧画面: カード列数と余白の調整
- モーダル: モバイル時の `fullscreen` または準全画面化

## 期待する効果
- モバイル対応の判断基準が明確になる
- 画面ごとのレスポンシブ設計のばらつきを抑えられる
- iPhone 13 実機確認とブラウザ確認の基準を一致させられる
- 今後の UI 改修でも、どの幅までを保証対象とするか判断しやすくなる
